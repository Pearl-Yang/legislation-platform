## 一、项目概述（限 2000 字以内）

### 1.1 项目背景

行政立法是法治政府建设的源头环节。截至 2024 年底，我国共有 5 部法律、30 部行政法规、8000 余部地方规章，每年新增地方规章 800 部以上。立法工作目前主要依据《行政法规制定程序条例》《规章制定程序条例》两部程序法规推进，覆盖立项、起草、审查、公布、备案、清理、评估等 10 余个法定环节，节点多、链条长、时限严。

但当前各级立法机关普遍面临"三难"困境：**起草难**——上位法条款的细化、地方实情的结合、异地经验的参考主要依赖起草者个人积累，效率低、周期长（平均 18 个月）；**审查难**——越权立法、引用失效法条、与上位法冲突等问题高度依赖人工核对，标准不统一、易遗漏；**清理难**——上位法一旦变动，涉及的下位法规数量多、影响范围广，依赖人工记忆排查容易遗漏；**评估难**——法规实施效果评估主观成分大，缺乏执法数据支撑，缺真实数据；**参与弱**——公众意见分散于网站、APP、座谈会、纸质件，渠道碎片化、归类统计困难。

### 1.2 应用行业

本项目面向**立法机关、政府法制部门、各级政府办公厅（室）**三大行业主体，可同时服务**法律科技（LegalTech）与数字政府**两个赛道，应用对象包括：

- 中央/省级/市级人大常委会法工委、政府司法局、法制办等立法起草审查部门；
- 国务院各部门、各省厅局承担规章起草任务的业务司局；
- "较大的市"人民政府及所属部门；
- 提供立法第三方评估、备案审查辅助的智库、律师事务所、信息化集成商。

### 1.3 需求分析

针对上述"三难"问题，本项目拟以"**AI 辅助 + 数据驱动 + 流程引擎**"为核心，搭建覆盖行政立法全生命周期的智能辅助平台，重点解决：

1. **起草效率低**：通过 RAG + LLM 自动提取上位法"需细化事项"、检索异地参考规章、生成条款草案，把起草周期从 18 个月压到 9-12 个月；
2. **审查标准不一**：通过 6 类规则引擎（上位法冲突 / 越权 / 引用失效 / 重复 / 格式 / 冗杂）+ AI 辅助建议，实现 90% 以上条款级自动审查；
3. **清理漏项**：通过 Neo4j 知识图谱建模法规上下级关系，上位法变动自动触发下位法规清理任务，联动率 100%；
4. **评估主观**：对接行政执法平台数据，从合法性、落实性、满意度三个客观维度量化打分；
5. **意见碎片化**：聚合 8 类渠道（Web、H5、小程序、政务APP、立法联系点、座谈、书面、来访），通过 AI 去重归类、词云统计、批量回复，实现结构化处理。

### 1.4 项目目标

平台总体目标是**"立法项目全流程线上管理 + 法规资料库 + AI 辅助起草审查 + 多渠道公众意见 + 实施评估"五位一体**，具体量化目标包括：

| 维度 | 现状基线 | 平台目标 |
|------|---------|---------|
| 起草周期 | 18 个月 | 9-12 个月（↓50%） |
| 审查人力 | 5 人/件 | 2 人/件（↓60%） |
| 清理漏项率 | 约 15% | <3% |
| 评估客观度 | 主观打分 | 数据驱动（执法数据 + 满意度） |
| 意见处理 | 7-15 天 | 24 小时内 AI 归类（↓80%） |

### 1.5 核心优势

项目具有以下 4 大核心优势：

1. **全流程闭环**：业界首个覆盖"立项 → 起草 → 审查 → 公布 → 备案 → 清理 → 评估"的端到端平台，区别于只做单点（起草 AI 或审查系统）的同类方案；
2. **AI + 知识图谱双引擎**：通义千问大模型 + Neo4j 法规关系图谱双轮驱动，AI 保证生成质量，图谱保证关系准确；
3. **强流程可配置**：将《行政法规制定程序条例》《规章制定程序条例》两条程序模板做成可配置数据，新法规类型 1 小时内可上线；
4. **数据要素全栈贯通**：从数据采集（爬虫 + 接口）→ 数据治理（Neo4j 关系建模）→ 数据应用（评估 / 决策）全链路打通。

#### 2.1.1 接入层

- **Web 管理后台**：Vue 3 + Vite + Element Plus，19 个核心业务页面 + 4 个图表组件（趋势图/饼图/柱状图/关系图），支持 PC Chrome/Edge 浏览器；
- **微信小程序**：uni-app 跨端框架，9 个核心页面（项目、草案、评估、清理、意见、资料、信息、登录、个人中心），方便立法工作人员移动端使用；
- **H5 公众页**：用于意见征集外部投放，免登录提交，支持匿名/实名。

#### 2.1.2 应用层

应用层是平台的核心，基于 **Spring Boot 3.1 + Java 17** 构建，包含：

- **14 个 REST Controller**：`LegislativeProjectController`、`DraftController`、`ReviewController`、`CleanupController`、`EvaluationController`、`ConsultationController`、`LibraryController`、`InfoController`、`RegulationController`、`AuthController`、`AdminController`、`AIAssistantController`、`CrawlerController`、`DocxExportController`；
- **9 个 Service**：`LegislativeFlowService`（流程引擎）、`DraftService`（AI 生成）、`ReviewService`（规则引擎）、`CleanupService`（清理编排）、`EvaluationService`（评估指标）、`ConsultationService`（意见处理）、`LibraryService`（资料检索）、`InfoService`（信息聚合）、`AuthService`（鉴权）；
- **AI 引擎**：`QwenFacade`（在线/离线统一入口） + `QwenApiClient`（DashScope OpenAI 兼容） + `OfflineQwenClient`（本地兜底），支持 `Qwen-Plus` / `Qwen-Turbo` / `Qwen-Max` 三档模型规格；
- **规则引擎**：`ReviewRule`（审查规则 6 类）+ `CleanupRule`（清理规则 3 类）+ `EvaluationIndicator`（评估指标 3 维），全部通过数据库可配置化；
- **异常兜底**：`@RestControllerAdvice` 全局异常 + `BizException` 业务异常 + 4xxxxx/5xxxxx 业务码统一返回；
- **异步任务**：`@Async` + `ThreadPoolTaskExecutor` 异步任务框架，草案生成、智慧审查、评估计算、清理联动 4 类重任务全部走异步，任务状态可查、可观测。

#### 2.1.3 数据层

- **MySQL 8.0 业务库**（24 张表）：覆盖立法项目、流程节点、期限、草案、审查、清理、评估、意见、资料、用户、消息 11 个子域，主键雪花算法、`is_deleted` 逻辑删除、Flyway 自动迁移；
- **Neo4j 5.x 关系图谱**（可选启用）：建模"法规 → 依据 → 上位法"、"法条 → 引用 → 法条"、"项目 → 关联 → 法规"三类关系，应用启动时 `Neo4jStartupSync` 全量同步 regulation + regulation_relation；
- **Redis 7 缓存**（可选）：`ConcurrentMapCacheManager` 内存缓存覆盖 Dashboard、regulationIndex、评估图表 3 个高频接口，切换 Redis 只需改 `legislation.cache.type=redis`；
- **外部数据**：`gov.cn` / `moj.gov.cn` 双源爬虫，**令牌桶限流 1 qps + 指数退避失败重试 + 断点续抓 checkpoint** 三重保障。

#### 2.1.4 可观测层

- **Prometheus** 抓取 `/actuator/prometheus` Micrometer 指标，覆盖 `legal_regulation_*` / `legal_draft_*` / `legal_review_*` 8 类业务指标；
- **Grafana** 现成大盘（`legal_dashboard.json`），含项目状态、草案生成速率、审查问题分布、清理任务进度、评估分数、意见分类 6 个看板；
- **ELK 风格 JSON 日志**：`logback-spring.xml` dev 走控制台、prod 切 JSON 到 `logs/app.json.log`，filebeat/logstash 直接采集；
- **OpenAPI 3 文档**：`scripts/export-openapi.sh` 一键导出 `openapi.json / openapi.yaml`，SpringDoc + Knife4j 双 UI 在线可访问（`http://localhost:8083/api/doc.html`）。

### 2.2 八大业务模块功能

平台围绕"行政立法全生命周期"设计 8 大功能模块：

### 2.3 关键技术

#### 2.3.1 大模型接入与 RAG

平台采用**通义千问（Qwen）大模型**作为 AI 能力底座，集成方式：

- **在线模式**：`QWEN_MODE=online` + `QWEN_API_KEY=sk-xxx` 接 DashScope OpenAI 兼容 API，支持 `qwen-plus` / `qwen-turbo` / `qwen-max` 三档；
- **离线兜底**：`QWEN_MODE=offline` 走 `OfflineQwenClient`（内置模板规则库），API Key 失效或网络中断时自动 fallback，日志输出 `[QWEN_OFFLINE_FALLBACK]` 提示；
- **RAG 检索增强**：基于法规资料库 + 异地参考规章做向量检索（MySQL FULLTEXT 索引 + 关键词 BM25），提示词工程（Prompt Template）模板化；
- **双通道切换**：`QwenFacade.execute(prompt, fallback)` 统一入口，业务代码无感知。

#### 2.3.2 知识图谱与关系建模

- **Neo4j 5.x 图数据库**部署为独立容器（`docker-compose.yml` 中 `neo4j:5`），`@ConditionalOnProperty(NEO4J_ENABLED=true)` 按需启用；
- **`Neo4jStartupSync`** `ApplicationReadyEvent` 钩子，启动时全量同步 `regulation` + `regulation_relation` 表到图谱，无 Neo4j 时降级到内存实现；
- **关系类型**：`SUPERIOR_OF`（上下级） / `REFER_TO`（引用） / `REPLACED_BY`（替代） / `ABOLISHED_BY`（废止） / `CITES`（法条引用）；
- **关系网可视化**：前端 ECharts `graph` 组件渲染 2 级关系网，节点支持点击钻取。

#### 2.3.3 规则引擎与可配置化

- **审查规则**（6 类）：`SUPERIOR_CONFLICT`（上位法冲突） / `OVER_POWER`（越权） / `OUTDATED_REF`（失效引用） / `DUPLICATE`（重复） / `FORMAT`（格式） / `VERBOSE`（冗杂），全部 `review_rule` 表可配置化，支持 JSON `check_logic` 表达式；
- **清理规则**（3 类）：日常 / 定期 / 专项，`cleanup_task` 表状态机管理；
- **评估指标**（3 维）：合法性（执法合规率） / 落实性（执行到位率） / 满意度（问卷 + 投诉），指标权重可调，`evaluation_indicator` 表管理。

#### 2.3.4 流程引擎

- **流程模板**：`legislative_stage_template` 表配置化，行政法规 / 部门规章 / 地方政府规章 3 套模板，按 `project_type` 区分；
- **节点操作**：提交 / 退回 / 驳回 / 加签 / 协办 / 中止 / 终止 / 恢复 / 延期 / 跳过 10 种操作枚举；
- **状态机**：`NOT_STARTED → PENDING → IN_PROGRESS → DONE/RETURNED/SKIPPED` 标准状态流转；
- **期限管理**：法定期限（如立项审查 30 日、部门会签 15 日）从模板自动带入，7 天内到期自动预警。

#### 2.3.5 异步任务框架

`@EnableAsync` + `ThreadPoolTaskExecutor` 配置（核心 8 线程 / 最大 16 / 队列 200），4 类重任务全部走异步：

1. **草案生成**（`/api/draft/generate`）：返回 `taskId`，前端 1.5 秒轮询 `/api/draft/generate/result/{taskId}`；
2. **智慧审查**（`/api/review/submit`）：异步执行 6 类规则；
3. **评估计算**（`/api/evaluation/{id}/chart-data`）：异步聚合 3 维指标；
4. **清理联动**（`/api/cleanup/task/{id}/suggest`）：AI 生成建议。

任务状态通过 `AsyncTaskRunner` 写入 `task_status` 表，可在 Prometheus 大盘观测 `legal_async_task_total` 计数。

#### 2.3.6 数据采集与治理

- **爬虫**：`gov.cn` / `moj.gov.cn` 双源，**令牌桶限流（1 qps）+ 失败重试（指数退避）+ 断点续抓（checkpoint 持久化）** 三重保障；
- **数据同步**：行政执法平台数据通过 REST API 定期拉取，写入 `evaluation_task` / `evaluation_result` 表；
- **数据校验**：通过 Bean Validation + 自定义校验注解，对外部数据进行 schema 校验、脏数据过滤。

### 2.4 数据要素利用方案

数据要素是本平台的核心生产资料，应用方式包括 4 个层次：

| 层次 | 数据内容 | 应用环节 | 价值体现 |
|------|---------|---------|---------|
| **原始数据** | gov.cn 抓取的法规 / 规章原文 | 资料库、图谱 | 提供基础语料 |
| **结构化数据** | 24 张业务表 + Neo4j 关系 | 流程、审查、清理 | 业务流转 |
| **AI 标注数据** | 审查规则 / 评估指标 / 意见分类 / 提示词模板 | 模型微调、规则引擎 | 知识沉淀 |
| **智能生成数据** | AI 生成的草案 / 审查建议 / 评估报告 / 意见回复 | 业务输出 | 提质增效 |

#### 2.4.1 数据来源广泛性

- **法规数据**：`gov.cn` / `moj.gov.cn` 官方源 + 司法部公报 + 人大立法规划库 + 33 个省级地方规章库；
- **执法数据**：对接省级行政执法综合管理监督信息系统，覆盖行政许可、行政处罚、行政强制、行政复议、行政诉讼 5 类数据；
- **社会数据**：政务服务平台意见数据、人大代表建议、政协委员提案、网络舆情；
- **平台自生产数据**：用户行为日志、流程节点时间、审查问题分布、评估分数、意见关键词。

#### 2.4.2 数据维度

平台数据维度涵盖 **5 个维度 / 24 个二级维度**：

- **法规维度**：层级（中央/省/市）、类型（法规/规章/规范性文件）、领域（30+ 行业）、时效（有效/失效/废止/修订中）、地区（31 省级 + 333 市级）；
- **流程维度**：阶段（10+ 节点）、状态（6 状态枚举）、操作人、时限、关联文档；
- **审查维度**：6 类规则 × 4 级严重度 × 条款级定位；
- **评估维度**：3 维指标 × 多期数据 × 横向对比；
- **意见维度**：分类（5 大类 / 14 小类）× 观点（支持/反对/中立）× 渠道（8 类）× 地域（31 省级）。

## 三、先进性（限 3000 字以内）

### 3.1 设计理念

平台以"**法律 AI × 数据要素 × 流程引擎**"为设计理念，遵循以下 4 项原则：

1. **法律严谨性优先**：所有 AI 输出必须可溯源、可校验、可干预，AI 仅作为辅助而非替代，最终决策权在立法工作人员；
2. **数据驱动决策**：用执法数据、评估数据、社会数据替代主观判断，让立法决策从"经验驱动"升级为"数据驱动"；
3. **流程可配置化**：把"立法程序"做成可配置模板，新增法规类型 / 调整节点顺序无需改代码，1 小时内可上线；
4. **全生命周期闭环**：覆盖立项到评估全环节，避免"信息孤岛"和"重复建设"。

### 3.2 独特优势与竞争优势

相比国内外同类方案，平台具有以下 4 项独特优势：

#### 3.2.1 全生命周期覆盖

- **国内同类**：北大法宝（资料库）、Westlaw（国外资料库）、华宇立法智能辅助系统（侧重起草）、科大讯飞智慧政务（侧重审阅）——多聚焦单点；
- **本平台**：**业界首个覆盖"立项→起草→审查→公布→清理→评估"全周期**的端到端平台，**立项后所有数据自动流转到下游模块**（如项目立项成功后自动初始化流程节点；草案生成后自动触发审查任务；审查通过后自动推进流程节点；公布后自动进入评估库；上位法变动后自动触发下级法规清理）。

#### 3.2.2 双引擎驱动（AI + 知识图谱）

- **AI 引擎**（Qwen 大模型 + RAG）保证**生成质量**（草案、审查建议、评估报告、意见回复）；

- 双引擎互为补充：AI 输出必须经图谱校验（不能与上位法冲突），图谱关系由 AI 辅助补全（自动提取引用关系）。

- 新增流程节点 / 调整节点顺序 / 调整法定期限，**仅需后台配置无需发版**，1 小时内可上线。
